# ADR-025 分析: MCPサーバー導入

- **判定**: 未実装 — Phase 2以降で検討
- **リスク**: なし（現時点で不在は問題ではない）
- **対象ファイル**: なし（新規作成が必要）

## StableBlockでの改善

Python FastMCPベースのステートフルサーバー。21ツールでLLMがDSL構文を知らずにブロック図を操作可能。

## StableStateの現状

MCPサーバーは存在しない。

## 分析

### MCPサーバーの価値

状態遷移図のDSL構文はブロック図より複雑（ガード条件、アクション、遷移種別、コンポジットステートのネスト等）であり、LLMによる自動編集の恩恵が大きい。

### 想定ツール

| ツール | 説明 |
|--------|------|
| `ss_add_state` | ステート追加（リーフ/コンポジット） |
| `ss_add_transition` | 遷移追加（イベント/ガード/アクション指定） |
| `ss_add_pseudo` | 擬似ステート追加（initial/final/choice/history等） |
| `ss_modify` | 要素の属性変更 |
| `ss_remove` | 要素削除 |
| `ss_validate` | 到達不能ステート、不完全遷移の検出 |
| `ss_auto_layout` | 階層構造を考慮した自動レイアウト |
| `ss_export_svg` | SVGエクスポート |

### 実装コスト

高（DSLパーサーのPythonポーティング、状態管理、テスト）。Phase 1完了後のPhase 2以降で取り組むのが適切。

## 推奨

Phase 2のスコープに含め、StableBlock MCPサーバーのアーキテクチャを参考に設計する。
