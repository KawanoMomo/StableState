# StableState ローカルIssueトラッカー 設計仕様書

## 概要

StableStateプロジェクトのバグ・改善・機能追加をローカルのMarkdownファイルで管理するissueトラッカー。GitHub Issues風の運用をGitリポジトリ内で完結させる。

## 方式

ハイブリッド方式: サマリーテーブル（ISSUES.md）+ 必要に応じた個別ファイル。

## ファイル構成

```
docs/issues/
├── ISSUES.md          # サマリーテーブル（インデックス、全issueを登録）
└── ISSUE-XXX.md       # 詳細が必要なissueのみ個別ファイル
```

## ISSUES.md フォーマット

```markdown
# StableState Issues

| ID | 種別 | 優先度 | ステータス | タイトル | 詳細 |
|----|------|--------|-----------|---------|------|
| 001 | 不具合修正 | HIGH | Open | タイトル | [詳細](ISSUE-001.md) |
| 002 | 改善 | LOW | Open | タイトル | - |
```

### テーブル列の定義

| 列 | 値 | 説明 |
|---|---|---|
| ID | 3桁の連番 | `001`, `002`, ... |
| 種別 | `不具合修正` / `改善` / `機能追加` | ECNの種別と同じ分類 |
| 優先度 | `HIGH` / `MEDIUM` / `LOW` | 対応の緊急度 |
| ステータス | `Open` / `Closed` | 未対応 / 対応完了 |
| タイトル | 短い説明 | 1行で内容がわかるもの |
| 詳細 | リンク or `-` | 個別ファイルがあればリンク、なければ `-` |

## 個別ファイル（ISSUE-XXX.md）フォーマット

ECNフォーマットベース。対策・結果欄は着手/完了時に記載。

```markdown
# ISSUE-XXX: タイトル

- **ステータス**: Open
- **種別**: 不具合修正 | 改善 | 機能追加
- **優先度**: HIGH | MEDIUM | LOW
- **発見日**: YYYY-MM-DD
- **影響ファイル**:
  - `対象ファイルパス`

## コンテキスト
何が問題か / 何を実現したいか

## 問題の詳細
再現手順や技術的な詳細

## 対策
（未記入 — 着手時に記載）

## 結果
（未記入 — 完了時に記載）
```

## 運用ルール

1. **全issueはISSUES.mdのテーブルに必ず登録**する
2. 簡単なものはテーブルの1行だけでOK（個別ファイル不要）
3. 背景説明や調査が必要なものだけ個別ファイルを作る
4. 対策を実施してECN化したら、ステータスを `Closed` にして対応ECN番号をテーブルに追記
5. IDは連番で欠番を作らない（削除ではなくCloseで管理）
