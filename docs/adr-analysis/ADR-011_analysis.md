# ADR-011 分析: スナップガイド性能

- **判定**: 要検討
- **リスク**: MEDIUM
- **対象ファイル**: `stablestate.html`

## StableBlockでの問題

スナップガイドが (1) renderSVGによるDOM破壊、(2) 複数スナップの競合ジッター、(3) 大規模図での性能劣化 の3段階で問題を引き起こし、最終的に機能を無効化。

## StableStateの現状

### DOM破壊問題（解決済）

スナップガイドは状態変数 `snapGuides`（line 270）に格納し、`renderSVG()` 内でSVG文字列に組み込む方式（line 1618-1627）。StableBlockの第1段階問題（DOM直接操作による消失）は回避されている。

### 複数スナップ競合（未検証）

```javascript
// stablestate.html:2602-2652
function computeSnapGuides(dragItems) {
  const threshold = 0.5 * g;
  ...
}
```

複数スナップ候補が同時に見つかった場合の選択ロジック（最近傍1つのみ適用）の有無を確認する必要がある。StableBlockでは全候補を同時適用して発振した。

### 性能問題（潜在リスク）

```javascript
// line 2612-2622: 全ステート・グループをイテレート
// line 2633-2650: ドラッグ中の要素と比較（O(n²)）
```

ドラッグの毎フレームで全要素との位置比較が発生する。ステート数が多い図（50+）では性能劣化の可能性がある。

## StableBlockとの比較

| 問題 | StableBlock | StableState |
|------|-------------|-------------|
| DOM破壊 | 発生→修正 | 設計段階で回避 |
| 複数スナップ競合 | 発生→修正→無効化 | 未検証（要確認） |
| 性能劣化 | 発生→無効化 | 潜在リスク |

## 推奨対策

1. **短期**: 大規模テスト図（50+ステート）でドラッグ操作の応答性を確認
2. **中期**: 複数スナップ候補の選択ロジックを確認し、必要に応じて最近傍1つのみ適用に修正
3. **長期**: 性能問題が顕在化した場合、空間インデックスの導入またはStableBlockと同様に機能無効化を検討
