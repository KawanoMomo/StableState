# ECN-001: 設計仕様の策定と改訂

- **ステータス**: 適用済
- **種別**: プロセス改善
- **対象コミット**: `b6ea3bb`, `f16324c`, `53e1fad`, `c0ab08c`, `b6d2bcf`
- **影響ファイル**:
  - `docs/superpowers/specs/2026-03-27-stablestate-design.md`
  - `docs/superpowers/plans/2026-03-27-stablestate-phase1.md`

## コンテキスト

StableStateプロジェクトの立ち上げにあたり、設計仕様書と実装計画書をコードより先に作成した。AUTOSAR状態遷移図エディタとして、DSL→SVGレンダリング、VSCode統合、双方向同期といった要件を事前に構造化ドキュメントとして定義する必要があった。

## 対策

1. **設計仕様書の作成**（`b6ea3bb`）: DSL構文、レンダリングルール、UIレイアウト、エクスポート仕様を含む460行の設計ドキュメントを作成
2. **仕様レビュー指摘の修正**（`f16324c`）: レビューで挙がったクリティカル/重要指摘を反映。状態スタイルDSL、バリデーションルール、ノート接続線、遷移種別、Undo/Redoセマンティクスを追加。SheetJS依存をCDNから組み込みに変更
3. **Phase 1実装計画の作成**（`53e1fad`）: 1,676行の段階的実装計画を策定。パーサ→バリデーション→レンダラ→UI→VSCode拡張の順序を定義
4. **ビジュアルグルーピング仕様追加**（`c0ab08c`）: StableBlock風の`group`キーワードによる非UMLグルーピング機能を仕様に追加
5. **オートルート仕様追加**（`b6d2bcf`）: ワンクリックで遷移線の交差を最小化するauto-route機能をPhase 2仕様に追加

## 結果

実装開始前に仕様と計画が確定し、Phase 1の全実装がこの仕様に沿って進行した。仕様先行により手戻りなくコアエンジンからVSCode拡張まで一貫した実装が可能になった。
